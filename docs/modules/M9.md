# M9 (menus-B + windows): working notes

Classes: HWWindow, HWWindowDelegate, SecondaryMenu, OptionsMenu, OptionsMenuItem,
AdvancedOptionsMenu, InfoMenu, Credits, CreditsLayer, PrivacyPolicyScene, ResetWorkaroundScene.

Status: Phase H (headers) done. Phase I (.cpp) DONE: all 10 classes implemented
(HWWindowDelegate is header-only). Every .cpp passes `tools/check_tu.sh` and was run through
`parity.py` (see "Phase I parity" below). Addresses are Ghidra addresses.

## Phase I parity (all remaining diffs explained)
Only noise remains: FUN_00a322f0 = `_Unwind_Resume` (we build with -fno-exceptions),
FUN_00572a20 = `__clang_call_terminate`, FUN_005a3f20/0058a96c/005a7808/0057f4dc = libc++
vector<Value>/ValueMap/basic_string helpers, NDK basic_string copy ctor vs
`__init_copy_ctor_external` (libc++ version), CREATE_FUNC/ctor/getLabelString/createMenuItemLabel
inlining differences, `GameText::get` extras (OW_GAMETEXT), `sdkbox::PluginReview::rate` (inline PC
stub), `std::function::swap` vs the original's out-of-line FUN_005a7dc4/005a8064, and "0.00781" /
"-3e-05" fmov "constants" that are parity.py misreading `movi v.2s,#0x3f,lsl#24` (= 0.5) and a
DAT_003f55c8 {0.5,-0.5} double load.
Credits font sizes are 150 (header) and 75 (0x42960000) for everything else (the notes below
said 90; fixed in the source). GameText keys (11): hwWindowPrivacyPolicyMessage/ReviewNote,
optionsUseLow/HighResGraphicsMessage, optionsStoreTransactionBusyMessage,
advancedOptions{DisableGore,ResetLevelProgress,ResetGame,SendFeedback,AdjustForNotch}Message,
infoMoreHappyWheelsMessage (all extract via tools/re/extract_gametext.py).
TU-local key strings are file-scope `static const std::string` in each .cpp (no shared header
exists in M10's code); privacy URL duplicated in InfoMenu.cpp and PrivacyPolicyScene.cpp as in
the binary.

## Phase H verification (re-run after any header edit)
* `bash tools/check_tu.sh build/tmp/m9_headers.cpp`: OK. OptionsMenu/AdvancedOptionsMenu are
  skipped via `__has_include` while M10's IAPControllerDelegate.h is missing.
* `bash build/tmp/m9_check.sh -fsyntax-only build/tmp/m9_headers.cpp`: the same flags plus
  `build/tmp/m9_stubs/` (a stand-in IAPControllerDelegate.h; the real header in src/game wins).
  Checks all 87 field-offset asserts and all sizeofs.
* `bash build/tmp/m9_check.sh -S -o build/tmp/m9_headers.s -Xclang -fdump-vtable-layouts
  build/tmp/m9_headers.cpp > build/tmp/m9_vt.txt`. Compared slot by slot with `owre.py vtable`:
  all 10 polymorphic classes match in entry count and method per slot.
* Destructors: the binary's D1 slot of OptionsMenu / InfoMenu / AdvancedOptionsMenu points at
  `SecondaryMenu::~SecondaryMenu`, and OptionsMenuItem's at `MenuItemLabel::~MenuItemLabel`. Clang
  only does that (replacing the derived D2/D1 with the base one) for a discardable, i.e. implicit
  or inline, trivial-bodied dtor, so those 4 classes declare **no** dtor. Only D0 has a symbol,
  emitted with the vtable. CreditsLayer / ResetWorkaroundScene / PrivacyPolicyScene have their own
  D1 that just re-stores the vptr, so they have user-declared out-of-line empty dtors.
* `python build/tmp/m9_plt.py <plt addr>` resolves `bl 0x00a3xxxx` PLT stubs to symbols. Example:
  OptionsMenuItem::unselected really calls `cocos2d::MenuItem::selected()` (0xa3b340).
* Bound member pointers checked: SecondaryMenu back button = {0x650, adj 1}, i.e. virtual
  backBtnPressed (AdvancedOptionsMenu's override runs). CreditsLayer::backBtnPressed is
  non-virtual. Menu callbacks use `std::bind(&X::menuItemPressed, this, _1)` / `btnPressed`.
