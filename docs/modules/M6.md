Parity noise legend (not logic differences):
* `FUN_00572a20` = `__clang_call_terminate`; `cocos2d::Vector<SpriteFrame*>::~Vector` missing = landing pad.
* parity.py reads `mov/movk` string immediates ("van.", "png") as fmov float constants.
* Original virtual-calls `init` in create() through the known vtable slot (r27 devirtualises).
* `FUN_00a322f0` = `_Unwind_Resume` (original built with exceptions; landing pads after
  `operator delete(p, nothrow)`); `FUN_0057f530` = `std::__tree_remove`; `FUN_005758f0` =
  `std::__tree_balance_after_insert`; `FUN_0057f8d8`/`FUN_0057587c` = vector length-error throws
  (ours: `__throw_length_error`/`__throw_bad_array_new_length`).
* libc++ r27 vs original: `basic_string(const basic_string&)` ↔ `__init_copy_ctor_external`.
* `X::~X()` D0/D1/D2 share one demangled name → parity compares the wrong variants.
* Out-of-line ctor called in the original but inlined by us (`Arrow::Arrow` in createWithPos).
* Clang tail-merges identical calls in if/else (e.g. both `Sound::setFinishCallback` in
  Arrow::createPrisJoint → one call site with two lambda vtables) → "missing x1".

Scratch helper `fdiff.py <Class> [substr]` (scratchpad/m6) compares per-function float-op mnemonic
sequences original vs rebuild (catches contraction/double-math mistakes parity.py cannot see).

Gotchas found while implementing:
* fp-contract is "on" (per expression) in the original too: `a*b + c` in ONE expression -> fmadd;
  products coming through Vec2 operators / separate statements are not fused. When the original shows
  fmul+fadd, split the product into its own statement/Vec2 temporary.
* `std::pow(float, 2)` = double math (`fcvt d; fmul d`) -> ArrowGun::fireArrow's quadratic.
* `fminnm`/`fmaxnm` = fminf/fmaxf/fmax (not b2Min/std::min, those give fcsel).
* `fcvtas` = (int)roundf(x) (Jet fps, Jet smash impulse).
* `x / 2` vs `x * 0.5f`: same value, but `/ 2` is not contracted into an fmadd (the original's
  sprite-centre maths in HarpoonGun::init uses `/ 2`).
* Harpoon::create / Arrow::createWithPos zOrder argument = `_turret->getLocalZOrder()` (vptr+0x30).
* **Ghidra hides rounding**: `fcvtpu` = `(unsigned)ceilf(x)`, `frintp` = `ceilf`. Every random
  sound/frame index (`"ArrowFlesh" + ceilf(rand01*3)`, `arrow_<ceilf(rand01*5)+1>`) needs the asm.
  Scratch helper `fconv.py <Class>` lists all fcvt*/frint*/fcsel per function.
* `b2Max`-style selects: `fcsel ..., gt` = `a > b ? a : b` (postSolve impulse max).
* Two field writes computed before either store (despite an external call in between) ⇒ the
  original built a `Vec2(...)` temporary (Arrow piece speeds).
* `LevelItem::s_timeStep` is read directly (ldr from the global), not via getTimeStep().

## Phase H decisions (headers)

* Layout verified with the NDK clang (same flags as `tools/check_tu.sh`) against M5's real
  `LevelItem.h`: a scratch TU with `#define protected public` + `static_assert(offsetof/sizeof)` for
  every member of all 11 classes passes, and the WreckingBall delegate sub-object is at 0x98.
  (Scratch file, not committed; recreate it if headers change.)
* Constructors declared only where the original had a user-provided one: Arrow, ArrowGun,
  HomingMine (out-of-line), HarpoonGun, Harpoon, WreckingBall (inline in the original — define them
  in the .cpp; no address of their own). Van/Mine/Jet/BladeWeapon/Spikes have NO user ctor so that
  `new (std::nothrow) X()` value-initialises (zero-fills) like the original; Spikes uses an NSDMI
  `_stabbableMaterials = 3`. **M4's LevelB2D::addSpecial must keep the `()`** on those news.
* Every class declares `~X() override` (vtable slot 1 shows X::~X). Jet/Mine/Van/WreckingBall
  dtors are empty (original: trivial, D1 aliased to ~LevelItem). ArrowGun/HarpoonGun/BladeWeapon/
  Spikes/HomingMine dtors only destroy members (implicit order matches the binary). Arrow and
  Harpoon dtors have real bodies.
* Non-virtual `init(b2Vec2, float, b2Vec2, int)` on Arrow/Harpoon hides LevelItem::init overloads
  (as in the original; vtables have no extra slot).
* Return types chosen (mangled names don't encode them): `ArrowGun::fireArrow → Arrow*`,
  `HarpoonGun::create → HarpoonGun*`, `Spikes::create → Spikes*`, `Harpoon::create → Harpoon*`,
  `HarpoonGun::getJoints → std::vector<b2DistanceJoint*>`, `WreckingBall::pointA/pointB/getPointA/
  getPointB → cocos2d::Vec2` (s0/s1 HFA, confirmed in asm), `BladeWeapon::getOpacity`/`Spikes::opacity → float`.
* Uninitialised-by-design (HomingMine is neither zero-filled nor fully ctor-initialised):
  `_explosionDistance` (init sets), `_lightColor`, `_pathClear`, `_skipAFrame`, `_counter` (p3),
  `_retargetCount`, `_totalImpulseVector`, `_mineBodyMassInv` (createBodies sets). Keep it so.
  HarpoonGun's ctor leaves `_anchorStart`; ArrowGun's ctor leaves `_turretPos/_turretLocalPos`.

## Global facts that matter for all M6 classes

* **Tail padding**: LevelItem data ends at 0x94 (`SpecialType` at 0x90, sizeof 0x98). A derived
  4-byte member lands at **0x94** (Itanium ABI tail-padding reuse): BladeWeapon `_stabCount`,
  Jet `_smashImpulse`, Spikes `_fixed` (bool) all sit at 0x94. Pointer members start at 0x98.
* **LevelItem fields I touch** (M5 must keep these names/accessible — `protected`):
  * `+0x40 std::map<b2Fixture*, std::string>` = iOS `_contactAddSounds` (Van::init inserts
    `"VanHit"`/`"CarTire1"` for its fixtures, Van::postSolve erases the body fixture).
    LevelItem::handleContactAdds plays them; contactSoundHandler(a,b,contact,f4) fills
    `+0x28 map<b2Fixture*,float>` (= iOS `_contactAddBufferDict`).
  * Nothing else below 0x98 is touched directly; everything else goes through LevelItem methods.
* LevelItem helpers used: `getSession() getLevel() getWorld() getPtm() getLevelBody()
  getLevelItemsNode()`, `loadSpriteFrames(LevelItemTextureId)` (0 = "level_items/level_items.plist",
  1 = "level_items/mineExplosion.plist"), `createBodySound(std::string, b2Body*, float, bool)` and
  `createPositionSound(std::string, cocos2d::Vec2, float, bool)` (return `Sound*`),
  `addToBeginContact/EndContact/PreSolve/PostSolve(b2Fixture*)`, `remove*` counterparts,
  `removeFromActions()`, `stopInteractivity()` (base, called at end of overrides),
  statics `s_timeStep` (read via `getTimeStep()` or directly), `s_timeStepOverFlashTimeStep`,
  `s_timeStepInverse`.
* `fixture->GetUserData()` is a `LevelItem*` (polymorphic). Code calls on it:
  vptr+0x68 `getFluidType()` (`== 1` → blood) and vptr+0x70 `shapeImpale(b2Fixture*, bool, b2Vec2, float)`
  (`== 1` → impaled flesh). Return types assumed `int` (compared with 1). Args seen:
  Arrow `(fixture, true, anchorWorldPoint, 0.01f)`, Harpoon/Blade/Spikes `(fixture, true, b2Vec2(INF,INF), 0.0f)`.
* Destruction/contact listener API (M5): `DestructionListener::addFixtureListener(b2Fixture*, LevelItem*)`,
  `addJointListener(b2Joint*, LevelItem*)` (Ghidra mislabels it `switchD_00a1e9ec::caseD_4d`),
  `removeFixtureListener(LevelItem*, b2Fixture*)`, `removeJointListener(LevelItem*, b2Joint*)`,
  `removeListeners(LevelItem*)`. `ContactListener::addPostSolveListener(b2Fixture*, LevelItem*)`
  (mislabeled `caseD_56`), `remove{Begin,End,PostSolve}ContactListener(b2Fixture*, LevelItem*)`.
* `LevelB2D::getFixtureMaterial(b2Fixture*)` returns a 32-bit material mask (0 if unknown, compared
  with `0xffffffff`): bit 1 (`& 2`) = flesh/stabbable. Items with `_stabbableMaterials` test
  `material & _stabbableMaterials` (uint16).
* `patch::to_string<unsigned int/int>(const T&)` (ostringstream) is a shared template (instances
  emitted in Arrow's TU @0057f2c4 and BladeWeapon's TU @0058559c). Needs a shared header — ask M10/M5.
* `globals::flash::ptmRatio` (const float, in .rodata @0041c0e8) is read directly in several places
  (`10.0f / ptmRatio` etc.) — distinct from `LevelItem::getPtm()` (Session's). M10 owns `globals::`.
* Every TU has an `_INIT_n` with `{0,0,0}`/`{0.1,0.5,0.5}` — that is cocos2d's
  `PHYSICSSHAPE_MATERIAL_DEFAULT`/`PHYSICSBODY_MATERIAL_DEFAULT` (CCPhysicsBody.h/CCPhysicsShape.h
  via cocos2d.h), not game code. Ignore.
* Construction styles (matters for zero-fill):
  * out-of-line user ctor: Arrow @0057d314, ArrowGun @005801fc, HomingMine @005c3034.
  * inline user ctor inside `create` (no symbol): HarpoonGun (create @005d07d4), Harpoon (create @005bf4e0),
    WreckingBall (inlined in LevelB2D::addSpecial case 7; sets secondary vptr at 0x98).
  * implicit ctor, `new (std::nothrow) X()` value-init (memset 0 first) in LevelB2D::addSpecial:
    Van (case 0, size 0xe0, Vec2 member re-zeroed), Mine (case 2, 0xc8), Jet (0x1c, 0xf8),
    BladeWeapon (0x22, 0x158; containers constructed after), Spikes (`Spikes::create` @005d09ec,
    0x160; containers + NSDMI `_stabbableMaterials = 3`).
  * Destructors: Jet/Mine/Van/WreckingBall have trivial (forwarding) dtors: vtable slot 0 is
    `LevelItem::~LevelItem` (alias), slot 1 their D0 that calls ~LevelItem + delete.
* Item type ids (LevelB2D::addSpecial): 0 Van, 2 Mine, 6 Spikes, 7 WreckingBall, 0xf HarpoonGun,
  0x19 HomingMine, 0x1c Jet, 0x1d ArrowGun, 0x22 BladeWeapon.
* Common inlined Box2D idioms: `SetLinearVelocity` (`if dot>0 SetAwake`), `SetAwake(true)`
  (`m_sleepTime=0; m_flags|=2`), `ApplyLinearImpulse(imp, worldCenter, true)` (wake if asleep,
  v += invMass*imp, w += invI*cross(c-c, imp) — note the zero cross because point == center),
  `SetAngularVelocity`, `GetWorldPoint` (`p + R*v`, Ghidra prints rev64/CONCAT soup),
  `b2BodyDef`/`b2FixtureDef`/`b2PolygonShape` default-ctor blocks (type at 0, etc.).
* Material/filter values: fixtures mostly `categoryBits 0x0008, maskBits 0xFFFF`; groupIndex
  -21 (0xffeb) for arrow/harpoon tips, -20 (0xffec) for gun sensors/ropes; 0 otherwise.
* std::function lambdas for `Sound::setFinishCallback(std::function<void(int&)>)` just clear the
  sound member: `[this](int&){ fleshSoundStopped(); }` etc. Named `$_0`,`$_1` in source order
  (flesh branch written first). `CallFunc::create(std::bind(&X::animationComplete, this))` for
  explosion animations.
