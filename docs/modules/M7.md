## General findings

* **Node/Layer/Sprite are 16-byte aligned** (std::function members), so every Node-derived
  sizeof is the data end rounded up to 16 (no hidden members: Gameplay 0x488->0x490,
  VictoryMenu 0x338->0x340, VictoryAnimation 0x328->0x330, DyingVignette 0x304->0x310).
* **Tail padding reuse**: LevelItem dsize 0x94; BoostPanel's first float sits at 0x94.
* `owre.py fields` misses accesses in functions Ghidra typed as static (`param_1` = this): all
  item `init`s, `createBody`s etc. — read them by hand.
* Header-inline `create` functions: `FinishLine::create` @005d06d4, `IBeam::create` @005d08e8
  (emitted in LevelB2D's TU after `LevelB2D::addSpecial`), `GameplayTimer::create` @005b9460
  (emitted in Gameplay's TU = CREATE_FUNC). PauseLayer/DyingVignette CREATE_FUNCs are fully
  inlined (Gameplay::pauseGameplay/handleDying), no symbol.
* Constructors: user-provided inline (no symbol): Log (in addSpecial), IBeam, FinishLine (in their
  create), GameplayTimer (in create). Implicit (factory value-initialises = zero-fill first):
  SpringBox, Fan, Sign, Bottle, SoccerBall, Token, Chain, SlowMotionPanel. Out-of-line: BoostPanel,
  Gameplay, GameplayControls, GameplayBtn, PauseLayer, VictoryMenu, VictoryAnimation, DyingVignette.
* Item factory = `LevelB2D::addSpecial` @005cff00 (M4). Type -> item: 3 IBeam::create (0xb8),
  4 Log (0xf0), 5 SpringBox (0xe8), 8 Fan (0x108), 9 FinishLine::create (0xf8), 10 SoccerBall (0x98),
  0xc BoostPanel (0x110), 0x14 Bottle (0xa8), 0x17 Sign (0xa0), 0x1e Chain, 0x1f Token,
  0x1389 SlowMotionPanel (0x98 each). Then `init` via vptr+0x18; on failure deleting dtor.
* Per-TU statics: every TU includes a shared header defining `{0,0}`, `{0,0}`, `{0.1f,0.5f}`,
  `0.5f` (M10's globals header, not ours). Ours:

## Control bits (GameplayBtn state values) — what a keyboard layer must emulate

`GameplayControls::getState()` = **sum** of `getStateValue()` of every button in `_buttons`
(+0x3c0) whose `getTouch() != nullptr`. Each frame `Gameplay::update` records it with
`ReplayData::addEntry(uchar)` (or, in replay, plays `getEntry()` back and only *displays* it with
`GameplayControls::setState`) and passes it to `CharacterB2D::setState(uchar)` (vptr+0x118) for
every character of the level (only while the level runs: not complete, character alive, not
dropped off-screen, `GameplayTimer::update()` true).

| bit | vehicle mode button (ControlsType 1..5) | `Vehicle` call (in vehicle) | ejected mode button (1000) | `CharacterB2D` call (ejected) |
|---|---|---|---|---|
| 0x01 | `controls_gameplay_btn_move.png` (bottom right) | `forwardButtonPressed()` | `controls_gameplay_btn_superman.png` (d-pad up) | `setCurrentPose(1)` superman |
| 0x02 | `controls_gameplay_btn_move.png` flippedX | `backButtonPressed()` | `controls_gameplay_btn_tuck.png` (down) | `setCurrentPose(2)` tuck |
| 0x04 | `controls_gameplay_btn_lean.png` | `leanForwardButtonPressed()` | `controls_gameplay_btn_arch.png` (left) | `setCurrentPose(3)` arch |
| 0x08 | `controls_gameplay_btn_lean.png` flippedX (bottom left) | `leanBackButtonPressed()` | `controls_gameplay_btn_pushup.png` (right) | `setCurrentPose(4)` pushup |
| 0x10 | special: `controls_gameplay_btn_{jump,break,jet}.png` | `special1ButtonPressed()` | `controls_gameplay_btn_grab.png` | `startGrab()` (else `endGrab()`) |
| 0x20 | – | – | – | – |
| 0x40 | – | – | – | – |
| 0x80 | `controls_gameplay_btn_eject.png` (top right) | `ejectAllCharacters()` | – | – |

Priorities (CharacterB2D::setState, M1): in vehicle 0x01 beats 0x02 (neither ->
`forwardBackButtonsNull`), 0x04 beats 0x08 (neither -> `leanButtonsNull`), 0x10 else
`special1ButtonNull`; ejected: pose priority 1>2>4>8, state==0 -> `doNothing()` only.
iOS had the same bits as `1 << tag` (tags 0..4, eject tag 7).
Pause/reset are NOT state bits: `_pauseBtn` (+0x3d8, tag 0) and `_resetBtn` (+0x3e0, tag 1, only
after death) dispatch custom event `"gameplayControlsAction"` (int* = tag) on touch-end inside the
hit area -> `Gameplay::handleControlsLayerAction` (0 pause, 1 reset).
In replay mode (ControlsModeReplay) touches never reach the state buttons; a touch shows the
"REPLAY MODE" overlay while held.

Special-button sprite per ControlsType (table @0041ba3c): 1 jump, 2 break, 3 jet, 4 jet, 5 jump;
other -> `controls_gameplay_btn_jump.png`. Characters.plist "controls": WheelchairGuy 3,
BusinessGuy 1, IrresponsibleDad 2, Shopper 1, MopedCouple 4, PogoStickMan 5.

* init: metrics `225s, (notch+450)s, 450s, 100s, (notch+60)s, 60s, 90s, 125s` (s = _userScale;

  "characterEjected" -> addControls(1000), "characterDead" -> handleDeath(), "banner_shown" /
  "banner_removed" -> body is just `getBannerAdSize()` (same as the three banner methods).
* addControls default branch order: move(1) right, move(2) flipped, lean(8) flipped far left,
  lean(4), special (0x10; sprite by type; left/right per "override_special_position" and
  `(type & ~4) != 1`), _pauseBtnPos, eject (0x80), optional debug rects, moped meter (type 4).

* handleDeath: mode 2 -> addControls(1002); remove meter; else addControls(1001), remove meter,

* touchBegan priority: pause (if enabled, free and hit) -> reset (same) -> replay mode: start
  indicator (once) -> else first free button whose hit area contains the point. Returns true if
  consumed (pause/reset/indicator/button) else false. touchMoved: transfer touches between
  buttons (release when leaving, pick up when entering). touchEnded: replay indicator removal
  (mode 2) else release the button holding it; then pause/reset hit test -> event.
* setMeterPercentage: rect = _meterBar->getTextureRect(); h = _originalMeterHeight * p;
  y' = (_originalMeterHeight - h) + _originalMeterY; rotated ? rect.origin.x = y' : rect.origin.y = y';
  rect.size.height = h; setTextureRect(rect, rotated, rect.size).
