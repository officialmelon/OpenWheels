# E3 — editor core (`src/editor/core/`)

Owner: editor agent E3. Ground truth: iOS 1.2.7 (`iosre.py fn/ivars/senders`, plus arm64
disassembly of the Mach-O for format strings and constants Ghidra drops). Phase H = headers and
contracts; Phase I = implementation — done: every `src/editor/core/*.cpp` and the hooked game TUs
pass `tools/check_tu.sh` (as do all other `src/editor/*/*.cpp` against these headers). The port
was then integrated into the MSVC build and run (see the end of this file).

## Coordinates, touches (port decisions)

* **UI space** = iPad points (iPad branch of every `userInterfaceIdiom` test). `EditorLayer` is
  `setScale(EditorAssets::pointsToDesign())` at the origin (anchor 0,0, content size
  `uikit::windowSize()`), so its children use the iOS numbers unchanged; `winSize` =
  `uikit::windowSize()`, `Screen::notchOffset` = `uikit::notchOffset()` (0). Editor-atlas UI
  sprites get `setScale(EditorLayer::pointSpriteScale())` (contentScaleFactor / pixelsPerPoint);
  `EditorLayer::pointSize(node)` / textureRect × scale give iOS point sizes. CCLabelTTF
  (ArialMT / Arial-BoldMT) → `Label` rendered at size × pointsToDesign and scaled back (sharp).
* **Stage space** (decided with E1/E2; `Special::editorArtScale()` + EditorLayer) is measured in
  **editor-atlas art units** (texture pixels / contentScaleFactor): 1 unit =
  `EditorLayer::stageUnitInPoints()` iPad points (0.5 on the large and medium tiers). Every stage
  sprite — refs whose own frame is the art (Mine, SoccerBall, HomingMine, SpringBox, Token) and
  child art alike — shows at its iOS size with node scale 1, and its selection box (`refRect` from
  `textureRect`) agrees; `Special::editorArtScale()` returns 1. Editor ptm =
  `EditorLayer::stagePtmRatio()` = 72 / stageUnitInPoints() (iOS iPad editor ptm 72, Session mode
  2), set with `Special::setSessionPtmRatio` before any ref exists; stage = ptm·320 × ptm·160 units
  (320 m × 160 m); the iOS stage display scales (initial 0.25, `centerToCharacter` 0.75, max 3) are
  multiplied by stageUnitInPoints(); the minimum `(winH − 60)/(ptm·160)` is already in units.
  Metres / XML are unaffected. Known deviation: point-valued inputs in EditParametersView
  (x, y, width…) show stage units (iOS points / stageUnitInPoints()).
* **Touch order**: iOS targeted priorities → cocos2d-x fixed priorities > 0 (after E4's
  scene-graph UIKit panels): buttons 1, batch node 2, EditorLayer 3, pan/zoom all-at-once 4 (iOS
  gives later-registered equal-priority handlers precedence, cocos2d-x the opposite; the numbers
  keep the iOS order). A non-swallowing one-by-one listener at −1000 closes the previous touch
  event's undo group (NSUndoManager groupsByEvent). PC addition (marked): mouse-wheel zoom on the
  stage around the cursor (same clamp as pinch).
* **Alerts**: UIAlertView → `Settings::createWindow(HWWindowAppearanceAlert, this, false, false)`
  + `showAlertMessage(title, message, cancelTitle, "")`. The intro alert is deferred one frame
  (`scheduleOnce`) because HWWindow attaches to the running scene, which during `init` is still
  the previous one.
* **Editor menu**: iPad path — `EditorPopoverController::create(menu)`, delegate callbacks bound to
  `popoverControllerShouldDismissPopover/DidDismissPopover`, content size 480 × 320,
  `menu->setPopoverController`, then presented from the 1×1 rect (menu.x, winH − menu.y), arrows
  any, not animated (iOS order). `removeMainMenu` dismisses it and calls `dismissRootPresented`.

## EditorUndoManager (NSUndoManager replacement)

Stack of groups of `{RefPtr target, std::function action}`: `registerUndo` / typed
`prepareWithInvocationTarget(target, lambda)`; nested `begin/endUndoGrouping` (flattened into the
parent); `groupsByEvent` implicit event group, closed by `endEventGroup()` (next scheduler tick, or
the EditorLayer −1000 touch listener); `levelsOfUndo` (SBN: 40, oldest dropped); registrations
while undoing go to the redo stack, normal ones clear it; `canUndo` also counts open groups (iOS
posts `undo_stack_updated` before the event group closes); `undo/redo` close the event group first;
`removeAllActions` also empties open groups (RE-TODO Foundation detail); Will/Did Undo/Redo
notifications. iOS fact kept: `undoAddRefs:` registers nothing, so redo after undoing an add only
restores the selection.

## levelData (XML writer)

From the `-[EditorLayer levelData]` disassembly (format strings read from the cfstrings):

```
<levelXML><info v="%.02f" x="%.02f" y="%.02f" c="%i" f="%i" h="%i" bg="%i" bgc="%i" e="1" fm="m"/>
  v = (double)1.7f -> "1.70"; x,y = refs[0].xMeters/yMeters; c = defaultCharacter; f, h, bg, bgc
refs[1..] in order: RefShape -> shapes, else specials
"<shapes>"   + per shape   "<sh t=\"%i\" i=\"%i\" " (levelItemID - 6000, interactive)
"<specials>" + per special "<sp t=\"%i\" " (levelItemID)
  per propertyKeys[k]: v = valueForKey(key) as -floatValue (BOOL -> 0/1)
     fmodf(v, 1.0f) == 0 ? "p%i=\"%i\" " (k, fcvtzs(v)) : "p%i=\"%.02f\" " (k, (double)v)
  then " />" (two spaces before "/>")
"</shapes>" / "</specials>" (only when non-empty), "</levelXML>"
```

No newlines, declaration or escaping; `snprintf` with the same formats; `fcvtzs` = arm64
float→int (truncating, saturating, NaN → 0).

## Loading a level into refs

`addLevelItems`: `EditorLevelXMLParser(levelMO->data(), this).parse()`, then
`undoManager()->removeAllActions()` and `undoStackUpdated(nullptr)`. `setVersion` →
`_bgIndex/_bgColor`; `addCharacter` → ref 5000, `setXMeters/setYMeters`, `setForceCharacter(f)`,
`setHideVehicle(h)` (NSString bool/int/float semantics), `createRef`, `addRef` (first ref →
`characterRef`, no undo), then `setDefaultCharacter(c < 2 ? 1 : c)`; `addShape` →
`addSingleItem(t + 6000)`, `addSpecial` → `addSingleItem(t)` = `EditorSettings::objectForKey` →
`setProperties` → `createRef` → `sbn->addRef` (unknown ids, e.g. SignRef 23 or polygons 6004/6005:
logged and skipped — iOS would throw). Editor XML has no `ptm`: values pass through as strings.
Shipped XML (OpenWheels extension): the iOS ptm/registration conversion per type is ported (shapes
p0..p3; special type mask 0x472909765 → p0/p1, 3/4 → p0..p3, 7 → p0..p2); groups/joints/triggers
are not parsed (the editor implements none of those delegate methods); port addition: Flash
booleans "t"/"f" become 1/0.

## Decisions

* **defaultCharacter is a character id.** iOS `-[Session setCharacterIndex:]` matches the value
  against `characters[i]["id"]` (`dictForCharacterIndex:`), CharacterRef stores the id
  (`_dictIndex` is the list index) and Android `LevelB2D::addInfo` reads `c` as an id.
  `applyLevelDataToSession` → LevelSession (`data`, `force_character`, `playable_character`,
  characterIndex = id, vehicle 0) + `Settings::setSelectedCharacterId(id)`; not restored after
  test play (iOS keeps the editor's character).
* Long hard-coded iOS text: the limit alert uses `OW_IOSTEXT(editorShapeArtLimitMessage, 0x1015d7e40)`
  (cfstring); short titles ("Shape Limit Reached", "Ugh, fine!") are literals.
