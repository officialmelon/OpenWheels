## iOS data model (happy_wheels_2.mom)

`LevelMO`: rating (double 0), comments (string), flags (int16 0), name (string), votes (int32 0),
plays (int32 0), importable (bool), id_x (int32 0), data (string = level XML), playable_character
(int16 0), active_x (bool), rating_total (int32 0), force_character (bool NO); relationships
chapter → ChapterMO (inverse levels), levelTimes → LevelTimeMO{time: float}, replays → ReplayMO
(cascade). No date attributes. `ChapterMO`: unlocked, chapterIndex (int16), name, levels,
prev/nextChapter.

User levels are ordinary `LevelMO`s in two special chapters: **5000** ("YOUR LEVELS": editor saves
and Documents-folder imports) and **5001** ("IMPORTED LEVELS": `.happywheels` files opened with the
app). `id_x` is a per-chapter sequence: new = `[levels sorted by id_x].lastObject.id_x + 1`.

Facts that shape the port:
* `-[Session chapterMOWithIndex:]` returns nil for 5000/5001 (`(i >> 1) == 2500`), so
  `Session.levelMO` is nil while a user level plays → `GameplayLayer handleLevelComplete:` never
  records completion times for user levels (`addCompletionTime:` sent to nil), and
  `advanceLevelIndex` returns NO. Consequently the "editing deletes best times" alert and the
  levelTimes purge in SAVE OVER never trigger in practice; both are still ported.
* Exits from CharacterSelectLayer / GameplayLayer go to `MainMenuLayer.scene` (not the level
  select) when chapterIndex is 5000/5001; `MainMenuLayer addPerspectiveCharacters` resets
  chapterIndex to 0 then.

## File format (LevelStore)

Under `FileUtils::getWritablePath()` (`%LOCALAPPDATA%\OpenWheels\` on Windows):

```
levels/index.plist          index (cocos2d ValueMap plist), written atomically (tmp + rename)
levels/<id_x>.xml           chapter 5000 level XML, verbatim LevelMO.data
levels/imported/<id_x>.xml  chapter 5001 level XML
levels/import/              drop folder for *.xml / *.txt  (= iOS Documents, file sharing)
levels/shared/              exports (ShareAction): <name>.happywheels + <name>.xml
```

`index.plist`: `{version: 1, levels: [entry...]}`, entry = `chapter`, `file` (relative to
`levels/`), every LevelMO attribute by its iOS name, `levelTimes` (float array), `createdOn`,
`modifiedOn` (double epoch seconds; port additions). XML is never in the index; `LevelMO::data()`
faults it in from `file`. A new level's file is `<id_x>.xml` (`_<n>` appended if taken).

Custom levels: loading the store adopts any `*.xml` in `levels/` (→ 5000) or `levels/imported/`
(→ 5001) that the index does not reference, if `isValidLevelXML` (tinyxml2: root `<levelXML>` with
`<info>`) accepts it: name = file stem, id_x = max + 1, playable/force character from
`<info c f>`; the file keeps its name and the index is rewritten. Entries whose file is gone are
dropped. `importLevelXMLFile(path)` imports one arbitrary file; `readHappyWheelsFile` +
`saveImportedLevel` handle `.happywheels` (plist: buildVersion, name, comments, data,
force_character, playable_character; ≤ 1 MiB).

## Store API

```cpp
LevelStore* s = LevelStore::getInstance();
ChapterMO* ch = s->chapterWithIndex(LevelStoreChapterUser);       // fetch chapterIndex == 5000
cocos2d::Vector<LevelMO*> v = s->levelsSortedById(5000);          // sorted by id_x
int last = s->lastLevelId(5000);                                  // 0 when empty
LevelMO* l = s->insertNewLevel();  l->setId_x(last + 1); ...; ch->addLevelsObject(l);
s->deleteObject(l);                                               // pending
std::string err; bool ok = s->save(&err);                         // commit (Core Data save:)
l->data(); l->name(); l->comments(); l->force_character(); l->playable_character();
LevelSession::getInstance()->setLevelDataWithManagedObject(l);    // Session
LevelSession::getInstance()->clearLevelData();
LevelSession::getInstance()->levelData();                         // Session.levelData (ValueMap&)
LevelSession::getInstance()->playLevel(force);                    // push gameplay / char select
```

Pending inserts/edits/deletes reach disk only on `save()` (all iOS callers save explicitly).
`LevelMO` objects are owned by their ChapterMO; screens hold them in `cocos2d::Vector`.
`save()`/`reload()` post `user_levels_changed` (uikit::NotificationCenter, object = store).

## Screen flows

**Save** (E4 `EditorMenuViewController::saveBtnPressed` → `SaveLevelViewController::create(menu._levelMO)`,
`setEditorLayer`, observers `save_level_cancel`/`save_level_done`, present):
* Fields start empty; counters `"%i %@"` (remaining, capitalized CHARS LEFT), limits 20 / 300 UTF-16
  units, Return in name → focus description, Return in description → end editing.
* No `_levelMO` and no `editorLayer.levelMO`: single SAVE button, SAVE OVER removed.
  Otherwise SAVE NEW + SAVE OVER and fields pre-filled from `editorLayer.levelMO`.
* SAVE/SAVE NEW: trimmed name empty → HEY / ENTER A NAME; untrimmed name equal to any chapter-5000
  name → HEY / ENTER UNIQUE NAME; else insert (id_x last+1, data = `editorLayer->levelData()`,
  name, comments, force_character, playable_character = `characterIndex()`), add to 5000,
  `editorLayer->setLevelMO`, Session `setLevelDataWithManagedObject`, tracker `save_level` /
  `count_<n>`, save → SUCCESS / LEVEL SAVED (tag 2) or `Error` / message / `Ok`.
* SAVE OVER (overwrite and the only rename path): writes name/comments/data/characters into
  `editorLayer.levelMO` without any name checks, deletes its levelTimes, save, same alerts.
* CANCEL: both fields blank → dismiss; else `Do Not Save?` / `Cancel the save?` NO/YES.
* Alert tag 2 (any) or tag 1 YES → post `save_level_done` and dismiss → EditorLayer
  `saveLevelComplete` sets hasSaved (**iOS quirk kept**: cancelling with text also counts as saved).

**Load** (E4 `confirmLoadLevel` after the unsaved-changes alert type 2 → `LoadLevelViewController::create()`):
two sections (5000 / 5001), "--" + SELECT A LEVEL placeholder, NO LEVEL DESCRIPTION fallback,
EDIT/SHARE disabled for imported levels. PLAY → LevelSession (chapter, id_x, levelData,
character, vehicle 0) → push gameplay (forced character) or character select, dismiss the menu;
EDIT → (levelTimes? "Hey" alert) → push `EditorLayer::createSceneWithLevelMO`; DELETE →
`"%@ \"%@\""` (DELETE THE LEVEL, name) / THIS CANT BE UNDONE / CANCEL / OK → deleteObject + save;
SHARE → ShareAction; NEW LEVEL → clearLevelData, replaceScene(`EditorLayer::createScene()`);
CANCEL → close. **iOS quirk kept**: edit/share index `_levels` whatever the section.

**Unsaved changes**: owned by E3/E4 (`EditorLayer::unsavedChanges() = canUndo && !hasSaved`,
menu "Hey / Lose changes?" before New (0), Exit (1), Load (2)). E5 only posts `save_level_done`.

Layouts: nib frames with autolayout resolved for the window (Load: panel (0,0,W,H-60), table
width W-258, right column x W-250 bottom-anchored; Save: panel (0,0,W,H-60), 20-pt margins,
buttons in the bottom 60 pt). Details in the headers.

## Phase I status

All classes are implemented, every iOS method tagged `// @ios`. `tools/check_tu.sh` passes for
all 11 TUs; the three that include `EditorLayer.h` (Load/Save/UserLevelSelect) currently fail only
because of E3's in-progress header (`editorUIView(...) override` while EditorLayer does not yet
derive from `EditorUIViewLayerDelegate`) and pass with that `override` removed.

**Character mapping (verified).** iOS `characterIndex` / `playable_character` / `<info c>` are
character **ids**: `-[Session dictForCharacterIndex:]` @ios 100042bb4 returns the Characters.plist
entry whose `id` matches. The iOS bundle's and the Android `shared/Characters.plist` list the same
six characters in the same order with the same ids (1 whe, 2 biz, 3 dad, 4 sho, 5 mop, 9 pogo), and
the Android `LevelB2D` reads `<info c>` as an id (`Settings::setSelectedCharacterId`). So
`LevelSession::applyToSettings` passes the value to `Settings::setSelectedCharacterId` unchanged.

**Build version.** `.happywheels` files carry `buildVersion` = iOS 1.2.7 `CFBundleVersion`
"0.9080" (`LevelSession::kBuildVersion`); `playImportedLevel` shows LEVEL INCOMPATIBLE when the
file's `buildVersion.floatValue` > 0.908 and plays anyway (iOS `fcmp s8, s0; b.le`).

**Alerts.** `levelui::showAlert` adds the HWWindow to the running scene at
`uikit::kWindowZOrder + 1`: `Settings::createWindow` uses z 10000, which is *below*
`uikit::window()` (100000), so alerts opened from an editor view controller would be hidden.
Screens retain themselves while their alert is up (released in `hwWindowWasDismissed`).
UIAlertView button index ↔ HWWindow tag: cancel only → index 0; cancel + other → other =
confirm (tag 1 → 1), cancel = tag 0 → 0; three buttons (IMPORT LEVEL?) → close button = cancel (0),
confirm = first other (1), HWWindow cancel slot = second other (2).

**Long iOS text.** `OW_IOSTEXT(editorEditDeletesBestTimes, 0x1015dcf40)`,
`OW_IOSTEXT(editorLevelsImportedMessage, 0x1015de700)` (both verified with
`extract_gametext.py`). Short hard-coded iOS strings are literals.

**APIs for the game hooks / entry points (E3, platform):**
* `LevelSession::getInstance()->isUserLevel()`: a 5000/5001 level is selected (skip
  `Settings::addCompletionTime`, exit/back to `MainMenu::createScene(MenuModeMain)`).
* `LevelSession::getInstance()->leaveUserLevel()`: chapterIndex 0 + clearLevelData (resets
  `Settings::setSelectedLevelFilePath("")`); call when the main menu / level select comes up.
* `UserLevelSelectUIView::scene()`: out-of-editor user-level picker (MainMenu button).
* `LevelSession::getInstance()->importLevelsFromFileSharingWithAlert()`: AdvancedOptions
  "import levels" (drop folder `levels/import/`).
* `LevelSession::getInstance()->openHappyWheelsFile(path)`: iOS openURL: (command line /
  drag & drop of a `.happywheels` file).
* `EditorLayer::sessionLevelData()` should return `LevelSession::getInstance()->levelData()`.

## Entry points

iOS: MainMenuLayer button tag 4 → `EditorLayer.scene` (new level); saved levels only through the
editor menu (Load); `.happywheels` files via `AppController application:openURL:` (IMPORT LEVEL?
alert: CANCEL / IMPORT AND PLAY / IMPORT); Documents-folder import via AdvancedOptions
"import levels" (Success / long message / Keep them / DELETE THEM). UserLevelSelectUIView /
SBSaveLevelViewController are never instantiated.

Port: editor button → `EditorLayer::createScene()` (E3); user-level picker
`UserLevelSelectUIView::scene()`; import via the two LevelSession calls above.

## Game hooks (implemented by E3, sole owner of src/game)

The level XML of a user level is passed through `Settings::setSelectedLevelFilePath(xml)` (Android
treats a non-empty value as XML text), so Gameplay/CharacterSelect/restart work unchanged. Needed:
* `leaveUserLevel()` when a campaign level is started from LevelSelectMenu / MainMenu is created;
* Gameplay victory: skip `Settings::addCompletionTime` (UserProgress) while `isUserLevel()`
  (iOS records nothing for user levels);
* exit / back from Gameplay and CharacterSelectLayer → `MainMenu::createScene(MenuModeMain)` for
  user levels; "next level" → level select (advanceLevelIndex NO).

## Deviations (each marked in the code)

* UserLevelSelectUIView ("iOS bug"): `descriptionText` key (crash) → `comments`; edit opens the
  selected level instead of an empty editor; delete saves the store.
* LevelStore import skips files that are not valid level XML; `readHappyWheelsFile` rejects an
  unreadable plist (iOS would import an empty level).
* `LoadLevelViewController::createNewLevelBtnPressed` also dismisses the root-presented editor
  menu (iOS leaves it up over the new editor with a dangling `editorLayer`).
* ShareAction (desktop has no share sheet): writes `levels/shared/<name>.happywheels` plus
  `<name>.xml`, replaces characters Windows forbids in file names, shows the path in an alert.
* LevelTextView: the caret stays at the end (arrow keys ignored), so every edit is an append or
  a backspace at the end.
