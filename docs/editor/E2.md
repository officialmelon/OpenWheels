# E2 — per-item editor references (`*Ref : Special`)

Owner: editor agent E2. Source: iOS 1.2.7 (`iosre.py fn/ivars <Class>`, plus arm64 disassembly for
varargs key lists and the float slider arguments that Ghidra drops). Game side:
`LevelB2D::addSpecial` and each item's `init(LevelDataElement*, ...)` in `src/game/items/`.

Status: Phase H (headers) and Phase I (`src/editor/model/<Class>.cpp` for all 19) done; every
TU passes `tools/check_tu.sh` against E1's `Special.h` and E4's InputObject headers.
Implementation notes (Phase I):
* Every iOS `set<Key>` setter opens `KeyValueChange kvo(this, "<key>")` first (E1's KVO rule),
  including the `setFixed`/`setInteractive` overrides (they chain to Special's, which nests).
* Each ref overrides `valueForKey`/`setValueForKey` for its own keys only (width/height,
  fixed, interactive route through Special's virtuals as well; handled explicitly for
  IBeam/Log width/height). NSNumber conversions use `kvcFloat/kvcInt/kvcUnsigned/kvcBool`;
  int/unsigned getters box as `Value(int)`, BOOL as `Value(bool)`, float as `Value(float)`.
* Labels are passed as Localizable keys (E4's InputObject localizes them). No long text, so no
  `OW_IOSTEXT`.
* Art scale (E1 review): every refRect / layout value derived from an art size
  (`getTextureRect()` / `getContentSize()` of a child or of the ref's own frame) is multiplied by
  `Special::editorArtScale()` so it is in iPad points, and every child art sprite gets
  `setScale(editorArtScale())` (times its iOS scale, e.g. ±1, 1.05, IBeam/Log/pole stretch).
  IBeam's remainder crop converts back to art units (`ptm·rem / editorArtScale`). Containers
  (`e_1x1` ball in WreckingBall) and the ref node itself keep their iOS scale (Jet still scales
  the ref with power). Touched: all refs except HomingMine and SoccerBall (no art-size code;
  Special covers their own frame).
* Float math follows the disassembly: fused `fmadd/fmsub` → `std::fma`, double steps kept
  (Harpoon base y, IBeam segment length, SlowMotionPanel outline), Session-ptm re-reads →
  `Special::sessionPtmRatio()`, ivar ptm → `_ptmRatio`.
* Quirks found while implementing (all kept): JetRef scales the **ref itself** with power and
  forces shape count 1 in `onEnter`; WreckingBallRef has no create hook and
  `setRopeLengthMeters` does not redraw, so loaded wrecking balls show the default 350 px rope
  until edited (init also sets `fixed = 1`); HarpoonGunRef's turret rotation is applied only
  by `setTurretAngle` (which bails out when unchanged, and the turret does not exist yet when
  `setProperties` runs), so a loaded fixed turret is drawn unrotated; `setUseAnchor` updates the
  shape count before its early-out; BladeWeaponRef `setBladeSliderIndex` indexes the table
  unchecked on iOS (guarded here, RE-TODO); IBeamRef tiles `e_ibeam.png` (alternating ±1.005
  scaleX, `fcvtmu` count, fmodf remainder piece with a cropped texture rect).

## Classes (19)

`iosre.py classes Ref` → every item ref not owned by E1 (E1: `RefShape` family, `CharacterRef`,
`DecorationRef`): ArrowGunRef, BladeWeaponRef, BoostPanelRef, BottleRef, FanRef, FinishLineRef,
HarpoonGunRef, HomingMineRef, IBeamRef, JetRef, LogRef, MineRef, SlowMotionPanelRef,

from `Special`. The game's `Sign` (23) and `Chain` (30) have no iOS editor ref.

## How serialization works (Special, owned by E1 — summarised because every ref depends on it)

* `-[Special initWithSpriteFrame:]` seeds `_propertyKeys` with
  **`xMeters, yMeters, angle, fixed, sleeping`** (refs that do not replace the list keep these).
* `-[Special properties]`: `t` = `levelItemID`; then for each key *i* of `propertyKeys`:
  `p<i>` = `[[self valueForKey:key] floatValue]` formatted `"%.02f"`, and if the string contains
  `".00"` the last 3 chars are dropped (`"5.00"`→`"5"`, `"5.60"` stays). Bools → `"1"`/`"0"`,
  which `LevelDataElement::boolAttribute` accepts; ints parse with tinyxml2 `QueryIntAttribute`.
* `-[Special setProperties:]` walks `p0, p1, …` while present and does
  `setValue:@(floatValue) forKey:propertyKeys[i]` — i.e. KVC by key name, values as numbers.
  **The C++ port therefore needs a per-key get/set on every ref** (see "Needs from E1").
* `propertyKeysForUI` (defaults to `propertyKeys`) lists what `EditParametersView` shows;
  each entry goes through `inputObjectForProperty:withRect:`. `Special`'s version only knows
  `x`, `y`, `angle` (InputObject + display field; angle 0..360, isAngleValue), `fixed`,
  `sleeping`, `interactive` (SwitchInputObject) and returns nil otherwise — so refs whose UI
  list uses `xMeters`/`yMeters` (Blade, Bottle, SoccerBall, Token) get **no** x/y inputs on iOS.
* Units: `xMeters = position.x / ptmRatio` (Session ptm); item lengths (`widthMeters`,
  `ropeLengthMeters`, …) are meters. Editor levels carry no `<info ptm>`, so `LevelB2D` uses
  `_sourcePtmRatio = 1` and `convertLengthData` is the identity → units agree.

## Interfaces used (resolved)

* E1 `Special.h`: `CREATE_FUNC(T)` + `bool init() override` (iOS `-init`), iOS `-create` →
  `virtual void createRef()`; KVC `valueForKey`/`setValueForKey` (virtual, chained);
  `KeyValueChange` KVO scope; virtual `setFixed/setInteractive(const Value&)`,
  `width()/height()/setWidth/setHeight(float)`, `updateDrawingWithNode(cocos2d::DrawNode*)`;
  `postNotification(REF_UI_KEYS_WILL_CHANGE|REF_UI_KEYS_CHANGED, this)`; `sessionPtmRatio()`
  for iOS `Session.ptmRatio` reads, `_ptmRatio` for the ivar; protected ivars `_fixed`,
  `_sleeping`, `_interactive`, `_propertyKeys`.
* E1 `EditorSettings` owns the item-id → ref registry (uses `T::create()`).
* E4: `SliderInputObject::create(frame, labelKey, property, initial, min, max, unsigned
  segments)`, `SwitchInputObject::create(frame, labelKey, property, initial)`; labels are
  Localizable keys (E4 localizes; the literal "strength" falls back to itself).
* Parameters the Android game ignores (Mine p5, SlowMotionPanel p3-p5, Log p7) are written
  exactly as iOS does (coordinator decision); the game keeps its Android behaviour.
